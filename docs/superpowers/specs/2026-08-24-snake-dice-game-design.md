# 뱀주사위놀이 (육성 버전) 웹 보드게임 — 설계서

작성일: 2026-08-24

## 1. 개요

1970~80년대 육성출판사 「뱀주사위놀이」(등록 제5386호) 보드를 웹 턴제 게임으로 옮긴다.
사람 1명과 컴퓨터 1명이 번갈아 주사위를 굴려 1번 칸에서 출발해 100번 칸에 먼저
도달하면 이긴다.

### 목표

- 주사위를 굴려 결과가 확정되기까지의 과정을 3D 애니메이션으로 연출한다.
- 보드 위 두 말을 색·아이콘·테두리 세 가지로 중복 구분한다.
- 원본 보드의 「고속도로」 13개와 「뱀」 12개를 그대로 재현하고, 각 칸의 교훈을
  카드로 보여 준다.

### 비목표 (YAGNI)

- 3인 이상 멀티플레이, 온라인 대전, 점수 저장, 다국어.
- 컴퓨터의 「전략」. 뱀주사위놀이는 선택지가 없는 순수 운 게임이므로 AI는
  주사위를 굴리는 것 외에 할 일이 없다.

### 저작권 (원본 그림)

원본 보드 그림은 **보호기간이 남아 있을 가능성이 높다**. 1980년 발행·출판사 명의로 보면
1957년법 30년 → 1987년법 50년 → 2013년 개정 70년으로 이어져 대략 **발행연도 + 70년**이다
(개정 시점에 살아 있던 저작물은 늘어난 기간을 그대로 받는다). 개인적 이용은 문제되지
않지만 **웹 공개·배포에는 허락이 필요하다**. 그래서 그림 없이도 완결되는 「레트로」
보드를 함께 유지한다 (8.1 참조).

## 2. 기술 스택

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 단일 `index.html` (CSS·JS 인라인) + `board.webp` | 더블클릭으로 바로 실행된다. 파일을 쪼개면 ES module 이 `file://` 에서 CORS 로 막혀 로컬 서버가 필요해진다 |
| 보드 | **원본 그림**(기본) / **레트로**(코드로 그린 것) 두 모드 | 원본 그림이 이 놀이의 정체성이라 기본으로 둔다. 레트로는 저작권 때문에 공개 배포가 필요할 때 쓸 수 있는 유일한 보드이자, 그림을 못 읽을 때의 폴백이다 |
| 빌드 | 없음 | 이 규모에서 번들러는 순비용이다 |
| 테스트 | 자동화 없음 | 브라우저 실행으로 경계값을 직접 확인한다 (6절) |

## 3. 보드 데이터

### 3.1 좌표계

10×10 부스트로페돈(소가 밭을 갈듯 방향이 번갈아 바뀌는 배열). 1번이 좌하단,
100번이 좌상단으로 원본과 같다.

칸 번호 `n`(1~100)에서 격자 좌표를 구하는 규칙:

```
i    = n - 1
row  = floor(i / 10)          // 0 = 맨 아래줄
col  = (row 가 짝수) ? (i % 10) : (9 - i % 10)
화면상 위에서 세어 top = 9 - row
```

- row 0 (1~10): 왼→오른쪽
- row 1 (11~20): 오른→왼쪽 (11이 오른쪽 끝)
- row 9 (91~100): 오른→왼쪽 (100이 왼쪽 끝)

## 4. 게임 규칙

원본 위키에 명시가 없는 항목은 아래대로 확정한다.

1. **시작**: 두 말은 **보드 밖(0번)** 에서 기다린다. 처음 굴린 눈만큼 판에 올라선다 —
   3이 나오면 3번 칸부터다 *(초기 설계에서는 1번 칸에 놓고 시작했다 — 8.16 참조)*.
2. **선공**: **무작위로 뽑는다.** 단 판이 끝나고 「계속하기」로 이어 가면 **진 쪽이 선**을
   잡는다. 시작할 때 누가 선인지 카드로 알린다
   *(초기 설계에서는 사람 고정이었다 — 8.14 참조)*.
3. **이동**: 주사위 눈(1~6)만큼 전진한다.
4. **6 재굴림** *(옵션 · 기본 꺼짐)*: 6이 나오면 같은 플레이어가 한 번 더 굴린다.
   단 **한 턴에 6이 3번 연속**이면 그 턴은 거기서 끝난다 (무한 루프 방지).
   3연속 6의 이동 자체는 무효화하지 않는다.
5. **끝내기**: 100번 칸에 닿으면 이긴다. **눈이 남아 넘어가도 그냥 이긴다** —
   99에서 6이 나오면 거기서 끝이다. 위키 원문의 "100에 도달하면 우승" 그대로다.
   *(초기 설계에서는 「정확히 도달, 넘으면 되돌아옴」으로 정했다가 8.11 에서 되돌렸다)*
6. **뱀/고속도로**: 이동이 끝난 칸이 시작점이면 즉시 도착 칸으로 옮긴다.
   연쇄 발동은 없다 (도착 칸이 또 다른 시작점인 경우는 이 보드에 존재하지 않는다).
7. **앞말 잡기** *(옵션 · 기본 꺼짐)*: 뱀/고속도로까지 모두 처리한 **최종 칸**에
   상대 말이 있으면 상대를 **1번 칸**으로 되돌린다. 잡힌 것이지 아직 출발 못 한 것이
   아니므로 보드 밖(0번)이 아니라 판 위 첫 칸이다.
   **2번 칸부터 따진다** — 0번은 아직 판 위가 아니고, 1번에서 잡아 봐야 되돌려 보낼 곳이
   그 자리라 의미가 없다. 100번 칸은 승리로 게임이 끝나므로 해당 없다.
   꺼져 있으면 두 말이 같은 칸에 겹쳐 선다.
8. **승리**: 100번 칸에 정확히 도달하면 즉시 승리.

### 4.1 한 턴의 처리 순서

```
굴림 → 전진(초과 시 되돌아옴) → 뱀/고속도로 발동 → 밀어내기 → 승패 판정
  → (6이었고 3연속이 아니며 승리하지 않았으면) 같은 플레이어 재굴림
  → 아니면 턴 넘김
```

## 5. 구현 구조

`index.html` 한 파일 안을 다섯 구획으로 주석 분리한다.

### 5.1 규칙 계층 (순수 함수, DOM 비의존)

```js
BOARD      // { highways: {4:16, ...}, snakes: {22:2, ...}, stories: {4:"...", ...} }
cellToXY(n)              → {col, top}         // 3.1 의 좌표 규칙
resolveMove(from, dice)  → {
  bounced: bool,         // 100 을 넘어 되돌아왔는가
  landed: number,        // 뱀/고속도로 적용 전 칸
  jump: 'highway'|'snake'|null,
  final: number,         // 최종 칸
  won: bool
}
```

애니메이션은 이 결과를 재생만 한다. 규칙과 연출이 섞이면 경계값을 눈으로만
확인해야 하므로 반드시 분리한다.

### 5.2 렌더링 계층

- **격자**: `<div class="cell">` 100개. 번호와 특수 칸 표식(`↗` / `🐍`)만 표시한다.
  잡다한 장식을 넣으면 말이 묻힌다.
- **오버레이 SVG**: `viewBox="0 0 1000 1000"`, `pointer-events:none` 로 격자 위에 겹친다.
  - 고속도로: 흰 리본 + 가운데 노란 점선 차선 + 도착점 화살표 (원본의 흰 도로 재현)
  - 뱀: 초록 물결 곡선. **머리는 도착 칸(작은 번호)** 에 눈·혀와 함께, 시작 칸에는 뾰족한 꼬리 (8.2 참조)
- **말**: 격자 위에 `position:absolute` 원형 토큰. `transform: translate()` 로 이동한다.

### 5.3 애니메이션 계층

| 연출 | 방식 | 시간 |
|---|---|---|
| 주사위 | CSS 3D `transform` 큐브. 굴리기 시작 시 **결과값을 먼저 확정**하고, 다축 회전 + 상하 바운스 후 `cubic-bezier` 감속으로 그 면이 정면에 오도록 착지 | ~900ms |
| 착지 강조 | 스케일 펄스 + 글로우 | 200ms |
| 칸 이동 | 한 칸씩 폴짝(위로 살짝 떴다 내려앉음) | 칸당 180ms |
| 뱀/고속도로 | 곡선을 따라 미끄러지는 별도 이동 | 700ms |
| 교훈 카드 | 화면 중앙 페이드인 → 유지 → 페이드아웃 | 총 1.8s |

주사위 눈은 CSS 3D 큐브의 여섯 면에 pip 을 배치하고, 값 → 최종 회전각 표를
고정해 둔다(예: 1 → `rotateX(0) rotateY(0)`).

### 5.4 턴 상태머신

```
IDLE ──(사람: 버튼 클릭 / 컴퓨터: 800ms 후 자동)──▶ ROLLING
ROLLING ──▶ MOVING ──▶ EVENT ──▶ BUMP ──▶ CHECK
CHECK ──(6 & 3연속 아님 & 미승리)──▶ IDLE (같은 플레이어)
CHECK ──(승리)──▶ GAME_OVER
CHECK ──(그 외)──▶ IDLE (턴 넘김)
```

`ROLLING`~`CHECK` 구간에서는 굴리기 버튼을 잠근다.

### 5.5 화면 배치

- 데스크톱: 좌측 보드(정사각, `clamp` 로 반응형), 우측 사이드 패널
- 사이드 패널: 플레이어 카드 2장(아이콘·이름·현재 칸·턴 표시) → 3D 주사위 →
  굴리기 버튼 → 진행 로그(최근 순)
- 모바일: 세로 스택 (보드 → 패널)
- 게임 종료 시 승자 오버레이 + 다시 하기 버튼

### 5.6 말 구분

| | 사람 | 컴퓨터 |
|---|---|---|
| 색 | 파랑 (`#2b6cff` 계열) | 빨강 (`#e2382d` 계열) |
| 아이콘 | 🧑 | 🤖 |
| 테두리 | 실선 | 이중선 |

색 하나에 의존하지 않으므로 색각 이상에서도 구분된다.
같은 칸에 겹치면 좌우로 어긋나게 배치한다.

## 6. 검증

빌드·테스트 프레임워크 없이, 완성 후 브라우저로 띄워 아래를 직접 확인한다.

| 항목 | 확인 방법 |
|---|---|
| 정확 도달 | 97에서 6 → 100 찍고 97로 되돌아오는지 |
| 되돌아온 칸의 뱀 발동 | 100 초과 후 착지 칸이 96/98이면 뱀이 도는지 |
| 밀어내기 | 상대가 선 칸에 도착 시 상대가 1번으로 가는지 |
| 6 재굴림 | 6 → 같은 플레이어가 다시 굴리는지, 3연속 6에서 턴이 끝나는지 |
| 즉시 승리 | 80 → 100 고속도로로 바로 이기는지 |
| 반응형 | 좁은 폭에서 보드가 깨지지 않고 말 좌표가 맞는지 |

경계값 확인을 위해 개발 중 콘솔에서 주사위 눈을 강제하는 디버그 훅
(`window.__forceDice = n`)을 둔다. 완성본에도 남기되 문서화하지 않는다.

## 8. 구현하며 바뀐 것

설계 후 실제로 만들면서 아래가 달라졌다. 이유를 함께 적는다.

### 8.1 원본 그림 배경을 기본으로 (설계에서는 쓰지 않기로 했었다)

원본 그림이 이 놀이의 정체성이라 기본 보드가 되었고, 코드로 그린 보드는 「레트로」 모드로 남겼다.

- `#board`(바깥 틀) 안에 `#grid`(10×10)를 두고, **두 모드가 같은 좌표 계산을 공유**한다.
  모드에 따라 `#grid` 의 위치·크기만 달라진다.
- 그림 안에서 격자가 차지하는 영역은 **이미지의 행·열 평균 밝기로 칸 경계를 검출해**
  최소자승으로 구했다(열 간격 50.9px, 행 간격 63.0px). 결과는
  `--grid-l: 1.06% / --grid-t: 15.83% / --grid-w: 97.79% / --grid-h: 83.11%`.
- 그림 크기는 하드코딩하지 않고 `measureBoardImage()` 가 실측해 `--img-w/--img-h` 에 넣는다.
  그림을 갈아끼워도 종횡비가 어긋나지 않는다.
- 레트로 보드도 **원본과 같은 크기·비율**을 쓴다. 전환해도 보드가 움직이지 않는다.
  원본의 제목판 자리에는 레트로 배너를 넣었다.
- 칸이 정사각이 아니게 되어(50.9 : 63.0) SVG 오버레이의 viewBox 를 `1000 x 1239` 로 잡았다.
  정사각 viewBox 를 늘려 쓰면 선 굵기가 가로·세로로 달라진다.

### 8.2 뱀의 머리는 도착 칸에

설계에서는 머리를 시작 칸(큰 번호)에 두었으나, 원본 보드는 반대다. 뱀은 미끄럼틀이므로
**꼬리(큰 번호)에서 타고 내려가 머리(작은 번호)에 잡아먹히는** 그림이 맞다.
시작 칸에는 뾰족한 꼬리를 그린다.

### 8.3 밀어내기는 최단 경로로

한 칸씩 되짚어 1번까지 가면 63번에서 밀리면 11초가 넘는다.
`knockTo()` 로 **곧장 날아가게**(540ms + 회전) 바꿨다.

### 8.4 효과음 (설계에서는 비목표였다)

음원 파일을 두면 단일 파일 원칙이 깨지므로 **Web Audio 로 그때그때 합성**한다.
주사위 구르는 소리·착지·칸 이동·뱀·고속도로·잡힘·승리 7종. 패널에서 끌 수 있고
선택은 `localStorage` 에 남는다. 오디오 컨텍스트는 사용자가 처음 누를 때 깨어난다.

### 8.5 안내 페이지

상단 「게임 안내」 버튼으로 같은 문서 안의 전체 화면 페이지가 열린다(별도 HTML 파일을 만들면
게임 상태를 잃는다). 개요와 방법을 한 페이지에 담고, **특수 칸 표 25행은 게임 데이터에서
자동 생성**해 규칙과 안내가 어긋날 수 없게 했다.

### 8.6 화면 정리

- 보드 선택·새 게임·게임 안내를 모두 상단으로 올렸다.
- 패널 높이를 보드에 맞추고 로그 카드만 남은 공간에서 스크롤한다.
  로그가 쌓여도 페이지가 보드보다 길어지지 않는다(항목은 60개로도 제한).
- 6이 나와 한 번 더 굴릴 수 있으면 주사위 아래에 알림이 뜨고 버튼 글자가 바뀐다.
- 잡혔을 때도 뱀·고속도로와 같은 카드로 알린다.
- **진행 로그는 뺐다.** 무슨 일이 일어났는지는 말의 움직임과 화면 가운데 카드가 이미
  다 보여 준다. 로그는 같은 내용을 글로 한 번 더 적는 자리였고, 그것 때문에 패널을
  보드 높이에 맞춰 늘이고 스크롤을 붙이는 규칙이 따라붙어 있었다. 함께 걷었다.

### 8.8 주사위 각도 정규화

`nextAngle()` 이 굴릴 때마다 앞으로만 돌리도록 각도를 더하기만 해서, **수십 번 굴리면
누적 각도가 수만 도**가 되었다(실측 44,460°). 화면상으로는 같은 자세라 눈에 띄지 않지만
쌓아 둘 이유가 없다. 착지 직후 `transition: none` 으로 0~360 범위로 되돌리고 강제
리플로우를 넣어 다음 굴림의 전이가 정상 시작되게 했다. 이제 최대 270° 를 넘지 않는다.

### 8.9 변형 규칙을 옵션으로, 새 게임 다이얼로그

**6 재굴림**과 **앞말 잡기**는 원본 판에 근거가 없는 변형 규칙이라 **옵션으로 빼고 기본을
꺼 두었다.** 기본 상태는 「굴린 만큼 가고 차례를 넘긴다」뿐이라 원본에 가장 가깝다.

- 보드 종류까지 합쳐 **`OPTIONS` 하나로 모으고** `localStorage` 키도 하나로 합쳤다
  (`snakegame.opts`). 예전의 별도 키 두 개(`snakegame.bg` / `snakegame.snd`)는 없앴다.
- 규칙은 **차례를 마무리할 때 읽는다.** 그래서 판 도중에 바꿔도 다음 차례부터 적용되고,
  이미 얻은 「한 번 더」를 도중에 빼앗아 진행이 꼬이는 일이 없다.
- **새 게임 다이얼로그**: 첫 진입과 「새 게임」·「다시 하기」에서 모두 이 창을 거친다.
  보드 종류는 고르는 즉시 뒤에서 바뀌어 눈으로 확인하고 시작할 수 있다.
  `Enter` 로 시작, `Esc`·바깥 클릭으로 닫힌다.
- **효과음만은 상단에 남겼다.** 음소거는 판을 새로 시작할 일이 아니라 지금 당장 필요한
  동작이라, 다이얼로그와 별개로 🔊 버튼을 두고 둘이 같은 `OPTIONS.sound` 를 본다.
- 상단에 만든 사람의 GitHub 링크를 넣고, 안내 페이지에도 저장소 주소를 적었다.

### 8.10 휴대폰에서 스크롤 없이 놀 수 있게

「모바일에서 스크롤 때문에 게임 진행을 할 수 없다」는 지적을 받고 다시 잡았다.
보드를 보면서 주사위를 굴려야 하는데 둘이 한 화면에 없으면 놀 수가 없다.

**화면 하나에 다 넣는다.** 휴대폰 세로에서 `body` 를 세로 플렉스로 세우고
`#boardWrap` 을 `flex: 1; min-height: 0` 로 두어 **남는 높이를 전부 보드가 가져간다.**
`body.no-scroll` 로 스크롤 자체를 잠근다.

**보드 크기는 상수가 아니라 실측으로.** `fitBoard()` 가 `#boardWrap` 에 실제로 남은
폭·높이를 재고 그림 종횡비로 맞춰 px 로 정한다. 너무 좁아지면(150px 미만) 억지로
우겨넣지 않고 스크롤을 다시 허용한다.

**주사위를 보드 위 오버레이로.** 보드에서 칸이 없는 곳은 **제목 띠(격자 위 15.83%)** 뿐이라
거기에 얹으면 **칸을 하나도 가리지 않으면서** 패널에서 주사위가 쓰던 높이를 통째로 보드에
넘길 수 있다. `position: fixed` 로 두고 `fitBoard()` 가 보드 위치를 재서 자리를 잡는다
(DOM 을 옮기지 않으므로 브레이크포인트를 오갈 때 상태가 깨지지 않는다).
패널에는 전폭 굴리기 버튼만 남는다.

**그 밖에 아낀 것**: 머리말을 한 줄로(75px → 38px), 「내 차례」 배지는 좁은 화면에서 감추고
카드 강조로 대신(배지가 50px 넘게 먹어 「1번 / 칸」으로 접혔다), Space 안내 문구 제거.

실측 (390 폭):

| 화면 높이 | 이전 보드 | 지금 보드 |
|---|---|---|
| 664 | 250 x 364 (36px 넘침) | **321 x 468** (넘침 0) |
| 844 | 339 x 494 | **358 x 522** (넘침 0) |

> **또 같은 함정**: `body` 를 세로 플렉스로 바꾸자 `#app` 의 `margin: 0 auto` 가 다시
> fit-content 를 유발해 폭이 199px 로 쪼그라들었다. 플렉스 항목에서 **자동 여백은
> stretch 를 이긴다.** `#boardWrap` 에서 한 번 겪고도 같은 자리에서 또 걸렸다 —
> 세로 플렉스로 바꿀 때는 자식들의 `margin: 0 auto` 를 함께 지운다.

### 8.11 정확 도달을 걷어냄

「99에서 6이 나오면 그냥 끝나야 하는데 100으로 갔다가 5칸 뒤로 간다」는 지적을 받았다.
설계 단계에서 「100 정확히 도달, 넘으면 되돌아옴」으로 정해 둔 그대로 동작한 것이지만,
**위키 원문은 "100에 도달하면 우승"일 뿐 되돌아오기는 내가 덧붙인 것**이었다.
잠깐 옵션으로 뺐다가, 필요 없다는 답을 받고 아예 걷어냈다.

`resolveMove()` 에서 `bounced` 를 없애고 `landed = Math.min(walkTo, 100)` 한 줄로 끝낸다.
턴 진행부의 「100을 찍고 되돌아오는」 두 단계 걸음도 함께 지웠다.

### 8.12 게임이 끝난 뒤

승리 창에 **계속하기**와 **그만하기** 두 갈래를 둔다. 계속하기는 설정 다이얼로그를
거쳐 다음 판으로(진 쪽이 선 — 8.15), 그만하기는 창만 닫아 **마지막 판을 그대로 볼 수
있게** 한다 (다시 하려면 위쪽 「새 게임」).

### 8.13 라이선스

코드와 문서는 **CC BY-NC-SA 4.0**(저작자표시-비영리-동일조건변경허락). 상업적 이용을
막고 2차 저작물에도 같은 조건을 요구한다. 칸 데이터와 설명이 나무위키
(CC BY-NC-SA 2.0 KR)에서 왔으므로 결이 맞는 선택이기도 하다.
`board.webp` 는 **이 라이선스의 적용 대상이 아니다** — 저장소가 재배포 권한을 줄 수 없는
남의 저작물이라 `LICENSE` 에 명시적으로 제외했다.

### 8.14 선을 무작위로

`resetGame()` 이 `state.turn` 을 매번 새로 뽑고, 누가 선인지 카드로 알린다.
컴퓨터가 선이면 카드를 읽을 틈을 주려고 첫 굴림만 1900ms 뒤로 미룬다
(`nextStep(cpuDelay)`).

**드러난 결함**: 선이 무작위가 되자 첫 진입에서 **설정 창이 열린 채 컴퓨터가 혼자
굴리기 시작했다.** 사람 고정일 때는 첫 차례가 늘 사람이라 버튼만 잠그면 됐기 때문에
드러나지 않던 구멍이다. `gamePaused()` 를 두어 창이 열려 있는 동안 `takeTurn()` 과
`nextStep()` 이 모두 멈추고, 「취소」로 닫으면 `closeSetup()` 이 `nextStep()` 을 다시
불러 멈춰 있던 판을 이어 간다. 「게임 시작」은 뒤이어 `resetGame()` 이 부르므로
`closeSetup(false)` 로 겹치지 않게 한다.

첫 진입의 `resetGame(false)` 는 설정 창 뒤에서 선 카드가 깜빡이지 않도록 조용히 돈다.

검증: 200회 뽑아 사람 선 106회 — 한쪽으로 쏠리지 않는다.

### 8.15 이어서 하면 진 쪽이 선

판이 끝나면 `nextFirst` 에 **진 쪽**을 담아 둔다. 승리 창의 **「계속하기」**로 이어 가면
그 값을 쓰고, 상단 **「새 게임」**은 이어서 하는 것이 아니므로 `nextFirst` 를 비워
다시 무작위로 뽑는다. 한 번 쓰면 곧바로 `null` 로 되돌려 다음 판까지 끌고 가지 않는다.

선 카드의 머리말이 상황을 구분한다 — 무작위면 「선 뽑기」, 이어서면 「진 쪽이 선」.
승리 창의 버튼도 「다시 하기」에서 **「계속하기」**로 바꿔 이어서 하는 판임을 드러냈다.

### 8.16 말은 보드 밖에서 출발한다

「게임을 시작하면 말들이 1번에 있는데 이건 잘못됐다 — 보드 밖에 있다가 처음 주사위를
던지면 그때 올라가야 한다」는 지적. **0번을 「보드 밖」으로 두면** 나머지는 그대로 맞는다.
`resolveMove(0, 3)` 이 3번을 돌려주고, 4가 나오면 4번 고속도로를 그대로 타고 16번으로
올라간다. `hopTo` 도 0에서 시작해 한 칸씩 올라오므로 「판에 올라서는」 움직임이 공짜로 나온다.

**대기 자리는 제목 띠 양끝.** 말은 `#grid` 의 자식이라 좌표가 격자 기준인데, `y` 를
음수로 두면 격자 위 제목 띠에 놓인다(`#board` 안이라 잘리지 않는다). 가운데는 휴대폰에서
주사위 오버레이가 얹히는 자리라 비우고 `x` 를 1.1칸 / 8.9칸 위치로 갈라 놓았다.
실측(390 폭): 사람 말 오른끝 85 · 주사위 164~226 · 컴퓨터 말 왼끝 305 — 겹치지 않는다.

**밀어내기의 목적지는 1번 그대로다.** 한때 0번으로 바꿨다가 되돌렸다 —
0번은 「아직 출발 못 한 상태」이고 밀어내기는 「판 위에서 잡힌 것」이라 뜻이 다르다.
새 판만 0번에서 시작하고, 잡히면 판 위 첫 칸인 1번으로 간다.
카드와 패널은 0을 「출발」·「출발 전」으로 적는다.

> **또 그 검증 함정**: 밀려난 말이 격자 밖에 있는지 `getBoundingClientRect` 로 쟀더니
> 실패했다. 인라인 transform 은 `-30.4px`(격자 위)로 정확한데 **렌더된 rect 이 전이가
> 얼어 옛 값에 멈춰 있었다.** 주사위에서 겪은 것과 같은 자동화 아티팩트다.
> 애니메이션이 걸린 요소는 rect 이 아니라 **목표값(인라인 스타일)으로 검증한다.**

### 8.17 「레트로」를 「요즘판」으로 — 같은 칸, 다른 시대

레트로 보드는 저작권 대비용 대체재일 뿐 존재 이유가 약했다. **같은 판에 지금의 이야기를
얹어** 원본과 견주는 판으로 바꿨다. 원본은 1970~80년대의 기록으로 남고, 요즘판은 지금의
이야기가 된다 — 둘을 나란히 두는 것이 이 게임의 재미가 된다.

- **칸 배치는 원본과 똑같이 둔다.** 두 보드가 기계적으로 완전히 같아서 판 도중에 바꿔도
  문제가 없고, 「같은 판 다른 이야기」라는 대비가 선명해진다.
- **이야기는 보드에 딸린다.** `STORIES_CLASSIC` / `STORIES_MODERN` 으로 나누고
  `stories()` 가 현재 보드에 맞는 것을 준다. 보드를 바꾸면 카드 문구도 함께 바뀐다.
- **시대를 타는 것만 바꿨다.** 간첩 신고 → 보이스피싱 신고, 전투 승리 → 헌혈,
  공부 게을리 → 밤새 영상, 닭 모이 → 텃밭, 개를 발로 참 → 남의 반려견.
  언 호수 스케이트나 불장난처럼 시대와 무관한 것은 그대로 뒀다.
- **칸 삽화 50개**(`ART` + `CELL_ART`). 번호(z:3) · 뱀·도로(z:2) · **그림(z:1)** 순으로 겹쳐
  원본처럼 그림 위로 뱀이 지나간다. 자세한 것은 8.18.
- 내부 값은 `"retro"` 를 그대로 쓴다(저장값·CSS 선택자 호환). 보이는 이름만 바꿨다.

**겹침 문제**: 그림을 넣자 뱀·도로가 그림을 덮어 판이 지저분해졌다. 뱀·도로를 얇게
(뱀 26/17 → 21/13, 도로 32/25 → 26/20) 하고 그림에 **밝은 테두리**를 둘러 겹쳐도 형체가
읽히게 했다.

안내 페이지의 표는 **칸 / 원본 판 / 요즘판** 3열로 바꿨다. 같은 칸이 시대에 따라 어떻게
달라졌는지가 이 표의 볼거리다.

### 8.18 칸 삽화 — 인과가 읽히게, 그리고 이모지에서 SVG 로

「고속도로와 뱀은 인과가 분명한 그림이어야 하는데 요즘판은 뜻 없는 그림의 나열이다」는
지적을 받고 두 번에 걸쳐 고쳤다.

**(1) 인과를 바로 세웠다.** 처음에 넣은 그림 여러 개가 **원인 자리에 결과를 그려** 놓았다 —
34번은 「성실히 일했다」인데 목돈을, 44번은 「친구를 때렸다」인데 다친 결과를, 68번은
「과식했다」인데 배탈을 놓았다. 도착 칸도 여러 개가 결과가 안 읽히는 그림이었다.
**시작 칸 = 한 일, 도착 칸 = 그래서 된 일**로 25쌍을 전부 다시 짰다.
가방→돈, 주먹→빠져나가는 돈, 햄버거→아픈 얼굴, 새싹→나무.

**(2) 홀수 칸을 비웠다.** 원본 판을 뒤져 보니 **고속도로·뱀이 쓰는 칸 50개가 모두 짝수**이고
그것이 2~100 의 짝수 전부다. 즉 홀수 칸은 하나도 인과에 쓰이지 않는다. 그래서 그림을
짝수 칸에만 두고 홀수 칸을 비웠다 — 원본의 격자무늬가 살아나고 뜻 없는 그림 50개가
사라졌다. `CELL_ART` 를 배열에서 **칸 번호 맵**으로 바꿨다.

**(3) 이모지를 버리고 SVG 로 직접 그렸다.** 이모지는 기기마다 그림이 달라지고 보드의
손그림 결과 이질적이다. 50장을 `ART` 에 SVG 로 그렸다 — 100×100 좌표계, 굵은 검정 외곽선,
납작한 레트로 색. 외곽선·선끝 처리는 `<svg>` 에 두어 각 도형이 상속하므로 도형 본체만 적는다.
이미 SVG 로 그려 둔 뱀·고속도로와 같은 결이 되어 판이 한 몸처럼 보인다.

그리고 나서 **50장을 한 판에 크게 펼쳐 눈으로 검수**했다. 청진기·기차·치킨·목발·셀카
다섯 개가 형태가 안 읽혀 각각 의사·기차 정면·햄버거·병원 침대·원근 선로로 다시 그렸다.
58번 이야기도 「개를 발로 차 쫓김」에서 「반려견을 괴롭히다 물림」으로 바꿔 결과(반창고)와 맞췄다.

> **함정**: 표의 삽화 칩에 쓴 `.art { width: 22px }` 가 보드 칸(`.cell.art`)에도 걸려
> **칸 폭이 47px 에서 22px 로 반토막** 났다. 칸 클래스를 `has-art` 로 바꿨다.
> 같은 이름의 클래스를 서로 다른 용도로 쓰면 이렇게 조용히 깨진다.

### 8.19 삽화를 이미지 모델로 갈아 끼우는 길

「픽토그램으로는 안 된다」는 판단에 따라, **이미지 모델로 만든 삽화로 바꿀 수 있는 길**을
열었다. 그림 자체를 지금 만들지 않아도 게임은 그대로 굴러가고, 나중에 파일만 넣으면 된다.

- **`docs/art-prompts.md`** — 프롬프트 팩. 공통 스타일 + 칸별 프롬프트 50개 + 출력 규격 +
  검수 기준. 제미나이 같은 이미지 모델에 그대로 넣는다.
- **`tools/gen-art.py`** — `google-genai` 로 한꺼번에 만든다.
  `--only` 로 한 장씩, `--force` 로 다시, `--convert` 로 손으로 받은 png 를 webp 로,
  `--manifest` 로 목록만 갱신. 한 장이 실패해도 나머지는 계속하고 끝에 실패 목록을 준다.
- **게임은 `art/NNN.webp` 가 있으면 자동으로 그것을 쓴다.** 코드를 고칠 필요가 없다.

**어느 칸이 있는지 어떻게 아는가** — 이것이 설계의 핵심이었다.

- 처음엔 4번 칸을 찔러 보고 있으면 50칸 전부에 `<img>` 를 붙이고 실패한 것을 걷어냈다.
  → 일부만 만든 상태에서 **404 가 47개** 쏟아졌다.
- 그래서 `art/manifest.json`(만든 칸 번호 배열)을 두고 **거기 적힌 칸만** 불러온다.
  스크립트가 매번 갱신하고, 손으로 넣었으면 `--manifest` 로 만든다.
- 다만 `file://` 로 열면 `fetch` 자체가 막힌다. **fetch 가 예외를 던졌을 때만**
  옛 방식(찔러 보고 전부 붙이기)으로 물러난다. 404 로 「없다」고 답한 경우는 답을 믿고
  끝낸다 — 그래서 삽화가 없을 때 실패 요청이 http 에서 1건뿐이다.

> **함정 하나 더**: 보드 전체에 `art-images` 클래스를 걸고 `.pic-svg` 를 숨겼더니
> **아직 안 만든 47칸이 빈칸이 되었다.** 그림이 실제로 `onload` 된 칸에만
> `.pic.has-img` 를 붙여 그 칸에서만 픽토그램을 감추도록 바꿨다.

삽화는 짝수 칸 50장뿐이고(8.18 참조), 새로 만든 그림이라 `board.webp` 와 달리
저작권 제약이 없다. 프롬프트에 원본 그림을 넣어 「이 그림처럼」 시키지 말라는 주의도
프롬프트 팩에 적어 두었다.

> **검증 도구가 틀렸던 사례**: 이 문제를 쫓다가 「주사위 표시면이 반환값과 다르다」는
> 실패를 만났는데, 원인은 게임이 아니라 검증 방식이었다. `getComputedStyle().transform`
> 은 전이 **중간값**을 돌려주는데, 자동화 브라우저가 전이를 얼려 버리면 그 값이 이전
> 굴림 상태에 멈춘 채로 남는다. 인라인 `style.transform`(목표 각도)으로 판정하도록
> 바꾸니 24회 굴림이 전부 통과했다. FACE_ROT 표는 각도를 직접 대입해 6면 모두
> 따로 확인했다.

### 8.20 6이 나오면 잠깐 1로 — 착지 섬광이 큐브를 납작하게 만들고 있었다

**원인은 `filter` 였다.**

```css
.dice.landed { animation: pop 220ms ease-out; }
@keyframes pop { 40% { filter: brightness(1.9) drop-shadow(0 0 14px #ffe25a); } }
```

`filter` 가 `none` 이 아닌 요소는 **`transform-style: preserve-3d` 가 강제로 `flat` 이 된다.**
`.dice` 가 바로 그 preserve-3d 컨테이너다. 그래서 착지 섬광이 도는 220ms 동안 큐브가
납작해지고, 90도로 세워진 면(2·3·4·5)은 폭·높이가 0으로 찌그러지고 뒤집힌 면(6)은
backface 로 사라져 — **회전이 없는 1번 면만 남는다.** 어떤 눈이 나오든 착지 순간 1로
보였고, 6은 정반대 면이라 가장 눈에 띄었다.

**고침은 한 줄이다 — 섬광을 큐브가 아니라 무대에 건다.**

```css
.dice-stage.landed { animation: pop 220ms ease-out; }   /* .dice 가 아니라 .dice-stage */
```

`.dice-stage` 는 `perspective` 만 가진 바깥 요소라 3D 렌더링에 참여하지 않는다.
안쪽에서 큐브를 3D 로 다 그린 뒤 그 결과 이미지에 효과가 얹히므로 자세가 온전하다.

> **오진을 하나 거쳤다.** 처음엔 굴림이 끝난 뒤 각도를 되돌리던 코드가
> `sleep(900)` 과 CSS 전이 900ms 의 어긋남 때문에 아직 구르는 전이를 끊는다고 보고,
> 전이를 버리고 Web Animations API 로 바꿨다. 그 변경 자체는 옳아서 남겼지만
> **증상은 그대로였다.** 「그럴듯한 원인」을 찾은 것으로 만족하고 증상을 눈으로
> 확인하지 않은 것이 잘못이었다.

**전이를 버린 것은 그대로 둔다** — 원인은 아니었지만 개선이다. 전이는 「지금 어느
자세인가」에 기대므로 구르는 도중 자세를 건드리면 반드시 튄다. 지금은 도착 자세를
먼저 인라인으로 확정해 두고 거기까지 가는 길만 `diceEl.animate()` 로 재생하므로,
끊겨도 마지막 키프레임(= 확정해 둔 도착 자세)으로 맞춰져 엉뚱한 면이 보일 수 없다.
배경 탭에서 `finished` 가 늦게 오는 경우를 위해 `DICE_SPIN_MS + 600` 상한을 두고
`anim.finish()` 로 끊는다.

> **검증 방법을 바꿔서야 잡혔다.** 이 자동화 브라우저는 `page.evaluate` 가 도는 동안
> 프레임을 거의 만들지 않는다 — 2초에 `requestAnimationFrame` 3회. 그래서 전이도
> 애니메이션도 진행되지 않고, 「자세가 몇 번 쓰이는가」 같은 **간접 지표**는 전부
> 통과하는데 증상은 남아 있었다. 결정타는 **정적 스크린샷**이었다.
> 큐브를 `rotateY(180deg)`(6번 면)로 세워 두고 `pop` 의 40% 값을 인라인으로 그대로
> 걸어 찍으니 눈이 하나로 나왔다 — 애니메이션을 재생할 필요조차 없었다.
> **움직임을 볼 수 없는 환경에서는 문제의 순간을 정지 상태로 재현해 찍는다.**

회귀 방지로 스타일시트를 훑어 **preserve-3d 요소에 `filter`·`opacity` 등 그룹화 속성을
거는 규칙이 없는지** 확인했다. `filter` 를 쓰는 키프레임은 `pop` 뿐이고, 이제 그것은
preserve-3d 가 아닌 `.dice-stage` 에만 붙는다.

### 8.21 요즘판도 그림 한 장으로 — 그리지 말고 찍는다

「원본처럼 이미지를 전체 한 장으로 만드는 게 관리가 편하지 않나」는 제안에 따라
요즘판을 원본 판과 같은 구조로 옮겼다. `board-modern.webp` 한 장에 격자·칸 번호·
뱀·고속도로·칸 그림이 모두 들어 있고, `data-bg="modern"` 은 `photo` 와 같은 규칙을 받는다.

**그림을 새로 그리지 않는다 — 게임 화면을 찍는다.** 이미지 모델은 10×10 격자에 100칸을
정확히 배치한 그림을 만들지 못한다(칸 수가 틀리고 경계가 어긋난다). 그런데 게임은
이미 그 전부를 정확히 그리고 있다. `tools/bake-board.py` 가 시스템 크롬으로
`index.html` 을 열어 요즘판을 `device_scale_factor` 로 3배 렌더하고 `#board` 를 찍는다.

- **좌표를 다시 잴 일이 없다.** 원본 판은 스캔 그림이라 격자를 밝기 최소값 검출 +
  최소자승으로 맞춰야 했지만(8.x), 이 그림은 게임이 그린 것이라 격자가 이미
  `--grid-*` 값 그대로다. 두 판의 격자 변수가 문자 그대로 같은 것을 확인했다
  (`1.06% 15.83% 97.79% 83.11%`).
- **`device_scale_factor` 로 키운다.** 창을 키우면 반응형 분기가 걸려 모바일 배치가
  나온다. 해상도만 올리면 데스크톱 배치가 유지된다.

> **★자기가 구운 그림 위에 다시 굽는 순환.** 굽기 스크립트가 `setBoardMode('retro')` 를
> 부르는데, 구운 그림이 이미 있으면 그것이 배경으로 깔린 채 그 위를 찍는다 —
> **두 번째 굽기부터 그림이 겹쳐 쌓인다.** `modernBaked = false` 로 코드 렌더를 강제하고,
> 찍기 직전에 `data-bg` 가 `retro` 인지 확인해 아니면 중단한다.
> (`probeModernBoard()` 가 뒤늦게 끝나 모드를 되돌릴 수 있으므로 두 번 못박는다.)

**코드로 그리는 경로는 지울 수 없다.** 그것이 이 그림을 굽는 원천이기 때문이다.
그래서 「그림 한 장이면 관리가 단순해진다」는 기대는 절반만 맞다 — 배포물은 한 장으로
줄지만 렌더링 코드는 그대로 있고, **칸 그림·이야기·격자를 고치면 굽기를 다시 해야
하는 단계가 하나 늘어난다.** 대신 `board-modern.webp` 가 없으면 코드 렌더로 물러나므로
그림을 받지 못한 상태에서도 게임은 온전히 돌아간다(폴백 검증 완료).

잃은 것도 적는다: 통짜 그림이 되면서 요즘판의 **DPI·테마 자동 대응이 사라졌다.**
1560×2274 로 구워 고DPI 화면까지 덮었지만, 그림이므로 그 이상은 늘어나지 않는다.

### 8.7 모바일 지원

설계에서는 `max-width: 900px` 에서 세로로 쌓는 것이 전부였다. 실제 휴대폰을 기준으로 다시 잡았다.

**세로 (≤ 700px)** — 8.10 에서 다시 손봤다. 아래는 그 이전 판이다.

- ~~보드 폭을 `calc((100svh - 300px) * ...)` 로 역산~~ → **상수가 틀렸다.** 실제 고정 요소는
  338px 였고 36px 이 넘쳐 스크롤이 생겼다. 게다가 `min-width: 250px` 바닥에 걸려
  보드가 250×364 로 쪼그라들었다. 8.10 의 `fitBoard()` 로 교체.
- ~~주사위와 굴리기 버튼을 한 줄에~~ → 주사위는 보드 위 오버레이로 옮겼다(8.10).
- 큐브 크기를 줄이되 면을 밀어내는 거리는 `--dz` 변수로 빼서 CSS 로 함께 줄인다
  (72px/36px → 52px/26px). 인라인 transform 에 박아 두면 화면 크기별로 못 바꾼다.
- 상단 버튼 네 개를 한 줄에 고르게 펴고 **높이를 40px 이상**, 굴리기 버튼은 52px 로 키운다.
- 안내 페이지는 테두리 없는 **전체 화면 시트**가 되고 닫기 버튼은 42px 다.

**가로 (높이 ≤ 560px)**

높이가 부족하므로 다시 좌우로 나란히 놓고, 보드 폭을 높이에서 역산하며 로그는 감춘다.

**터치 일반**

- `viewport-fit=cover` + `env(safe-area-inset-*)` 로 노치·홈 인디케이터를 피한다.
- `touch-action: manipulation`(더블탭 확대 지연 제거), `-webkit-tap-highlight-color: transparent`,
  `user-select: none`. 안내 페이지 본문만 선택·복사를 되살린다.
- **주사위를 눌러도 굴러간다.** 터치에서 가장 자연스러운 동작이다.
- 안내 문구는 `(hover: none)` 으로 입력 방식을 보고 고른다 — 마우스 없는 기기에
  「Space 키」를 안내해 봐야 소용없다.
- 안내 페이지를 열면 `body` 스크롤을 잠그고 `overscroll-behavior: contain` 으로
  스크롤이 뒤 페이지로 넘어가지 않게 한다.
- 방향 전환·주소창 접힘에도 말이 칸에서 벗어나지 않도록 `resize` 와
  `orientationchange` 에서 다시 앉힌다.

**함정 하나**: `#app { align-items: center }` 로 두면 `#boardWrap` 이 shrink-to-fit 이 되어
그 안의 `#board` 가 쓰는 `width: 100%` 가 순환 참조로 무너진다(`min-width` 까지 쪼그라들어
보드가 250px 가 됐다). `align-items: stretch` 로 두고 `#boardWrap` 안에서 가운데 정렬한다.
가로 배치로 돌아갈 때는 세로용 `margin: 0 auto` 도 함께 지워야 한다 — 자동 여백이 남는
공간을 다 먹어 보드가 왼쪽 끝으로 밀린다.
